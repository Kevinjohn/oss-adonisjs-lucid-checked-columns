# Decision gaps and boundaries

The catalogue describes the reviewed source and identifies version-specific release boundaries.

| Gap or boundary             | Guide and source evidence                                                                                                                                                                                                                             | Catalogue treatment                                                                                           | Resolution needed                                                      |
| --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Exception API before v0.4.0 | [v0.3.3 documentation](https://github.com/Kevinjohn/oss-adonisjs-lucid-checked-columns/blob/v0.3.3/README.md#errors) describes plain errors. [source exports](../index.ts) and [classes](../src/errors.ts) provide `errors`, stable codes and fields. | Stories 01, 02 and 05 describe the reviewed source interface; the guide links v0.4.0.                         | Use v0.4.0 or later to match the documented exception constructors.    |
| Shared JSON diagnostic      | [Both exception classes](../src/errors.ts) use `Invalid persisted JSON in <table>.<column>` even when preparation refuses an input.                                                                                                                   | Story 01 distinguishes write and read by exception class/code rather than message alone.                      | Retained current diagnostic; any wording change is a product decision. |
| Model path only             | The [guide](../README.md#limits) says query-builder writes bypass hooks.                                                                                                                                                                              | Stories 01/02 describe hooks; 03 reports metadata only. The host owns any validation, encoding and raw write. | No new enforcement is implied.                                         |
| Dirty tracking              | The [guide](../README.md#limits) and [model test](../tests/json_column.spec.ts) record a top-level `isDirty: false` value causing an update to be skipped before preparation.                                                                         | Story 01 shows the skipped path and recommends avoiding that key.                                             | Arbitrary top-level keys require a Lucid dirty-tracking change.        |
| Driver representation       | The [guide](../README.md#api) requires JSON text and describes the ambiguity of native scalar strings; the [consumer](../examples/release-consumer/model.ts) exercises SQLite text columns.                                                           | Stories describe hook contracts and the candidate fixture; no other driver round trip is claimed.             | Driver-specific integration remains host-owned.                        |
| Stronger ISO policy         | The [guide](../README.md#api) says the generic cannot enforce host-specific rules; [source](../src/iso_column.ts) checks canonical syntax only.                                                                                                       | Story 02 assigns stronger checks before writing and after reading to the host.                                | Host defines and enforces its own policy.                              |

The [0.3.2 changelog](../CHANGELOG.md#032---2026-11-23) records that v0.3.0 added the `/types` entry; its original v0.3.0 entry remains as published. These retained boundaries are not product fixes.
